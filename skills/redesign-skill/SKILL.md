# Redesign Skill

## 運作方式

套用到既有專案時，依照這個順序進行：

1. **掃描（Scan）** — 讀過整個程式碼庫。辨識框架、樣式撰寫方式（Tailwind、原生 CSS、styled-components 等）以及目前的設計手法。
2. **診斷（Diagnose）** — 跑一遍下面的稽核清單。列出你找到的每一個平庸手法、弱點與缺漏的狀態。
3. **修正（Fix）** — 在既有技術棧上做針對性的升級。不要打掉重寫，把現有的東西改好。

## 設計稽核

### 字體排印（Typography）

檢查以下問題並修正：

- **用瀏覽器預設字體，或到處都是 Inter。** 換成有個性的字體。好選擇：`Geist`、`Outfit`、`Cabinet Grotesk`、`Satoshi`。編輯風／創意類專案可用襯線標題搭配無襯線內文。
- **標題沒有存在感。** 展示型文字加大字級、收緊字距、降低行高。標題應該顯得厚重且有意圖。
- **內文行寬過寬。** 段落寬度限制在大約 65 個字元。提高行高以利閱讀。
- **只用了 Regular（400）與 Bold（700）兩種字重。** 導入 Medium（500）與 SemiBold（600），做出更細膩的層級。
- **數字用比例字體。** 資料密集的介面請改用等寬字體，或啟用表格數字（`font-variant-numeric: tabular-nums`）。
- **沒有調整字距。** 大標題用負字距，小型大寫字或標籤用正字距。
- **到處都是全大寫的次標題。** 改試小寫斜體、句首大寫（sentence case）或 small-caps。
- **孤字（orphan）。** 單一個字孤零零留在最後一行。用 `text-wrap: balance` 或 `text-wrap: pretty` 修掉。

### 色彩與表面

- **純 `#000000` 背景。** 改用近黑、深炭黑，或帶色調的暗色（`#0a0a0a`、`#121212`，或深海軍藍）。
- **過飽和的強調色。** 飽和度壓在 80% 以下。把強調色去飽和，讓它融入中性色而不是尖叫。
- **強調色超過一個。** 選一個，其他拿掉。一致性勝過多樣性。
- **暖灰與冷灰混用。** 固定用同一個灰色家族。所有灰色都用一致的色相調色（要暖就全暖，要冷就全冷，不要混）。
- **紫藍色的「AI 漸層」美學。** 這是最常見的 AI 設計指紋。改用中性基底搭配單一、經過斟酌的強調色。
- **千篇一律的 `box-shadow`。** 把陰影調成呼應背景色相。使用帶色陰影（例如藍色背景配深藍色陰影），而不是低不透明度的純黑。
- **完全沒有質感的扁平設計。** 在背景加上細微的噪點、顆粒或微圖樣。純扁平向量顯得很無菌。
- **過於均勻的漸層。** 用放射漸層、噪點疊層或網格漸層（mesh gradient）打破均勻感，別再用標準的 45 度線性漸層。
- **光源方向不一致。** 稽核所有陰影，確保它們指向同一個一致的光源。
- **亮色頁面裡隨機出現暗色區塊（或反過來）。** 在一個原本明亮的頁面中插入單一深色背景區塊，看起來就像複製貼上的意外。要嘛就做完整的暗色模式，要嘛整頁維持一致的背景色調。如果需要對比，用同一色盤中稍深的色階——而不是在一片米色頁面中間突然跳到 `#111`。
- **空洞、扁平、毫無視覺層次的區塊。** 只有文字放在素背景上的區塊會顯得沒做完。加上高品質的背景影像（模糊、疊色或加遮罩）、細微圖樣或環境漸層。沒有真實素材時，可用可靠的佔位圖來源，例如 `https://picsum.photos/seed/{name}/1920/1080`。在主視覺區、功能區塊或 CTA 後面試試背景圖——就算只是低不透明度的滿版照片，也能大幅增加存在感。

### 版面（Layout）

- **所有東西都置中又對稱。** 用偏移邊距、混合長寬比，或在置中內容上方放置靠左對齊的標題來打破對稱。
- **三個等寬卡片欄組成的功能列。** 這是最平庸的 AI 版面。改用兩欄 zig-zag、不對稱網格、水平捲動或磚牆式（masonry）版面。
- **全螢幕區塊使用 `height: 100vh`。** 改用 `min-height: 100dvh`，避免行動瀏覽器上的版面跳動（iOS Safari viewport bug）。
- **複雜的 flexbox 百分比運算。** 改用 CSS Grid 來做可靠的多欄結構。
- **沒有 max-width 容器。** 加上容器寬度限制（大約 1200-1440px）並設定 auto margin，避免內容在寬螢幕上被拉到滿版。
- **flexbox 強制卡片等高。** 內容長度不一時，允許高度變動或改用 masonry。
- **所有元素圓角一模一樣。** 讓圓角有變化：內層元素收緊，容器放柔。
- **沒有重疊也沒有層次。** 元素平鋪在彼此旁邊。用負 margin 製造層疊與視覺深度。
- **上下 padding 完全對稱。** 上下 padding 永遠一樣。請做視覺上的微調——下方 padding 通常需要稍微大一點。
- **儀表板一定配左側邊欄。** 改試頂部導覽、浮動命令選單，或可收合面板。
- **留白不足。** 把間距加倍。讓設計呼吸。密集版面適合資料儀表板，不適合行銷頁。
- **卡片群組中的按鈕沒有靠底部對齊。** 卡片內容長度不同時，CTA 會落在高低不一的位置。把按鈕釘在每張卡片底部，這樣不論上方內容多長，按鈕都能排成一條乾淨的水平線。
- **功能清單的垂直起始位置不一。** 在價目表或比較卡片中，功能清單應該在所有欄位都從同一個 Y 座標開始。清單上方請使用一致的間距，或固定標題／價格區塊的高度。
- **並排元素的垂直節奏不一致。** 把卡片、欄位或面板並排時，要讓共通元素（標題、說明、價格、按鈕）跨項目對齊。基線沒對齊會讓版面看起來壞掉。
- **數學上對齊、視覺上卻歪掉。** 用數字算出來的置中，眼睛看起來不一定是置中。文字旁的 icon、圓形內的播放鍵、按鈕裡的文字，往往需要 1-2px 的視覺補償才會對。

### 互動與狀態

- **按鈕沒有 hover 狀態。** 加上背景變化、輕微縮放或位移。
- **沒有 active／按下的回饋。** 按下時加上細微的 `scale(0.98)` 或 `translateY(1px)`，模擬實體按壓感。
- **轉場時間為零的瞬間切換。** 為所有互動元素加上平滑轉場（200-300ms）。
- **缺少 focus ring。** 確保鍵盤操作時有可見的焦點指示。這是無障礙需求，不是可選項。
- **沒有載入狀態。** 把千篇一律的圓形轉圈換成符合版面形狀的骨架載入（skeleton loader）。
- **沒有空狀態。** 一個什麼都不顯示的空儀表板是浪費機會。設計一個編排過的「開始使用」畫面。
- **沒有錯誤狀態。** 為表單加上清楚的行內錯誤訊息。不要用 `window.alert()`。
- **死連結。** 連到 `#` 的按鈕。要嘛連到真實目的地，要嘛在視覺上停用它。
- **導覽列沒有標示目前頁面。** 把 active 的導覽連結做出不同樣式，讓使用者知道自己在哪。
- **捲動跳動。** 錨點點擊瞬間跳位。加上 `scroll-behavior: smooth`。
- **用 `top`、`left`、`width`、`height` 做動畫。** 改用 `transform` 與 `opacity`，取得 GPU 加速的流暢動畫。

### 內容

- **像「John Doe」或「Jane Smith」這種罐頭姓名。** 使用多元、聽起來真實的名字。
- **像 `99.99%`、`50%`、`$100.00` 這種假的整數。** 使用有機、不那麼工整的資料：`47.2%`、`$99.00`、`+1 (312) 847-1928`。
- **像「Acme Corp」、「Nexus」、「SmartFlow」這種佔位公司名。** 自己發明貼合情境、可信的品牌名。
- **AI 文案的老套字眼。** 絕對不要用 "Elevate"、"Seamless"、"Unleash"、"Next-Gen"、"Game-changer"、"Delve"、"Tapestry" 或 "In the world of..."。用平實、具體的語言寫。
- **成功訊息裡的驚嘆號。** 拿掉。要有自信，不要大聲。
- **「Oops!」式的錯誤訊息。** 直說：「連線失敗，請再試一次。」
- **被動語態。** 改用主動語態：「我們沒能儲存你的變更」，而不是「發生了一些錯誤」。
- **所有部落格文章日期都一樣。** 把日期隨機化，看起來才真實。
- **多個使用者共用同一張頭像。** 每個不同的人都要用不同的素材。
- **Lorem Ipsum。** 絕對不要用拉丁文佔位字。寫真實的草稿文案。
- **每個標題都用 Title Case。** 改用句首大寫（sentence case）。

### 元件手法

- **千篇一律的卡片外觀（邊框＋陰影＋白底）。** 拿掉邊框，或只用背景色，或只用間距。卡片只有在「高度差能傳達層級」時才該存在。
- **永遠一個實心按鈕＋一個幽靈按鈕。** 加入文字連結或第三層樣式，降低視覺雜訊。
- **膠囊形狀的「New」與「Beta」標章。** 改試方形標章、旗標，或純文字標籤。
- **手風琴式 FAQ 區塊。** 改用並排清單、可搜尋的說明中心，或行內的漸進式揭露。
- **三卡輪播＋圓點的推薦區。** 改成磚牆式評論牆、嵌入的社群貼文，或單則輪替引言。
- **三根柱子的價目表。** 用顏色與強調來凸顯推薦方案，而不是只把它做高一點。
- **什麼都用 modal。** 簡單操作改用行內編輯、側滑面板（slide-over）或可展開區塊，不要動不動就彈窗。
- **頭像清一色圓形。** 試試 squircle 或圓角方形，看起來比較不平庸。
- **亮／暗模式切換永遠是太陽／月亮開關。** 改用下拉選單、偵測系統偏好，或整合進設定頁。
- **四欄式的頁尾連結農場。** 簡化。聚焦在主要導覽路徑與法規要求的連結。

### 圖示（Iconography）

- **清一色使用 Lucide 或 Feather 圖示。** 這些是 AI 的「預設」圖示選擇。改用 Phosphor、Heroicons 或自訂圖示組來做出區隔。
- **「Launch」配火箭、「Security」配盾牌。** 把老套的隱喻換成不那麼明顯的圖示（閃電、指紋、火花、保險庫）。
- **各圖示的線條粗細不一致。** 稽核所有圖示，統一成同一個筆畫粗細。
- **缺少 favicon。** 一定要放上有品牌的 favicon。
- **罐頭的「多元團隊」照片。** 用真實團隊照、抓拍照，或一致的插畫風格，取代那種詭異的圖庫照。

### 程式碼品質

- **Div soup。** 使用語意化 HTML：`<nav>`、`<main>`、`<article>`、`<aside>`、`<section>`。
- **行內樣式與 CSS class 混用。** 把所有樣式移進專案的樣式系統。
- **寫死的像素寬度。** 使用相對單位（`%`、`rem`、`em`、`max-width`）做出彈性版面。
- **圖片缺少 alt 文字。** 為螢幕閱讀器描述圖片內容。有意義的圖片絕對不要留 `alt=""` 或 `alt="image"`。
- **像 `9999` 這種隨便亂給的 z-index。** 在 theme／變數中建立一套乾淨的 z-index 級距。
- **被註解掉的死程式碼。** 上線前把所有除錯殘留清乾淨。
- **幻覺 import。** 檢查每一個 import 是否真的存在於 `package.json` 或專案相依套件中。
- **缺少 meta 標籤。** 補上妥當的 `<title>`、`description`、`og:image` 與社群分享 meta 標籤。

### 策略性遺漏（AI 通常會忘記的事）

- **沒有法務連結。** 在頁尾加上隱私權政策與服務條款連結。
- **沒有「返回」導覽。** 使用者流程走進死路。每一頁都要有回去的方法。
- **沒有自訂 404 頁。** 設計一個有幫助、有品牌感的「找不到頁面」體驗。
- **沒有表單驗證。** 加上前端驗證，檢查 email、必填欄位與格式。
- **沒有「跳至內容」連結。** 這對鍵盤使用者很關鍵。加上一個隱藏的 skip-link。
- **沒有 cookie 同意。** 若所在司法管轄區有要求，加上合規的同意橫幅。

## 升級手法

升級專案時，從這些高效手法中取用，來取代平庸的做法：

### 字體排印升級
- **可變字體動畫。** 隨捲動或 hover 內插字重或字寬，讓文字有生命感。
- **描邊轉填色。** 文字先以描邊呈現，在捲入視野或互動時填上顏色。
- **文字遮罩揭露。** 用大型字體當作窗口，透出後方的影片或動態影像。

### 版面升級
- **破格網格／不對稱。** 刻意無視欄位結構的元素——重疊、出血到畫面外，或以計算過的隨機量偏移。
- **極大化留白。** 積極運用負空間，強迫視線聚焦在單一元素上。
- **視差卡片堆疊。** 區塊在捲動時吸附並實際堆疊在彼此之上。
- **分割畫面捲動。** 畫面左右兩半朝相反方向滑動。

### 動態升級
- **帶慣性的平滑捲動。** 讓捲動脫離瀏覽器預設，做出更有重量的電影感。
- **交錯進場。** 元素以微小延遲依序串連進場，結合 Y 軸位移與透明度淡入。絕對不要全部同時掛載。
- **彈簧物理。** 把線性緩動換成彈簧式運動，讓所有互動元素都有自然、有重量的手感。
- **捲動驅動的揭露。** 內容透過擴張遮罩、抹除效果，或與捲動進度連動的 SVG 路徑描繪來進場。

### 表面升級
- **真正的玻璃擬態。** 不要只停在 `backdrop-filter: blur`。加上 1px 內邊框與細微的內陰影，模擬邊緣折射。
- **聚光邊框。** 卡片邊框隨游標動態發亮。
- **顆粒與噪點疊層。** 一層固定的、`pointer-events-none` 的細微噪點疊層，打破數位的扁平感。
- **帶色調的陰影。** 讓陰影帶有背景色相，而不是使用通用的黑色。

## 修正優先順序

依照這個順序改動，能以最低風險換到最大的視覺提升：

1. **換字體** — 立即見效最明顯，風險最低
2. **色盤整理** — 拿掉互衝或過飽和的顏色
3. **hover 與 active 狀態** — 讓介面活起來
4. **版面與間距** — 妥當的網格、max-width、一致的 padding
5. **替換平庸元件** — 把老套手法換成現代替代方案
6. **補上載入、空、錯誤狀態** — 讓成品有「做完了」的感覺
7. **打磨字級與間距** — 高階感的最後一道工

## 規則

- 在既有技術棧上做事。不要遷移框架或樣式函式庫。
- 不要破壞既有功能。每次改動後都要測試。
- 引入任何新函式庫之前，先檢查專案的相依套件檔。
- 如果專案用 Tailwind，修改設定前先確認版本（v3 還是 v4）。
- 如果專案沒有框架，就用原生 CSS。
- 保持改動易於審查、聚焦。小而精準的改進勝過大規模重寫。
