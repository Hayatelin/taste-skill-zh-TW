# Design System: Taste Standard
**Skill:** stitch-design-taste

---

## 設定 — 調出你的風格
使用這套設計系統前，先調整下面這幾個旋鈕。它們控制產出要多有創意、多密集、多動態。挑一個符合你專案的等級。

| 旋鈕 | 等級 | 說明 |
|------|-------|-------------|
| **創意度（Creativity）** | `8` | `1` = 極簡、瑞士風、安靜、單色。`5` = 平衡，乾淨但有個性。`10` = 表現性強、編輯風、大膽的字體實驗、標題內嵌行內圖片、強烈不對稱。預設：`8` |
| **密度（Density）** | `4` | `1` = 藝廊般空靈、大量留白。`5` = 平衡的區塊。`10` = 駕駛艙式密集、資料量大。預設：`4` |
| **變異度（Variance）** | `8` | `1` = 可預測的對稱網格。`5` = 細微的偏移。`10` = 藝術性混沌，沒有兩個區塊長得一樣。預設：`8` |
| **動態意圖（Motion Intent）** | `6` | `1` = 靜態，不註明動畫。`5` = 細微的 hover／進場提示。`10` = 每個元件都註明電影感的編排。預設：`6` |

> **使用方式：** 把上面的數字改成符合你專案 vibe 的值。**創意度 1–3** 時，系統會產出乾淨、安靜、類似 Notion 的介面。**創意度 7–10** 時，可以預期會出現行內圖像字體排印、戲劇性的大小對比，以及強烈的編輯風版面。底下其餘規則會隨你選的等級調整。

---

## 1. 視覺主題與氛圍
一個克制、藝廊般空靈的介面，搭配自信的不對稱版面與流動的彈簧物理動態。氛圍冷靜卻不失溫度——像一間採光良好的建築工作室，每個元素都靠功能掙得自己的位置。密度平衡（等級 4），變異度偏高（等級 8）以避免對稱帶來的無聊，動態流暢但絕不誇張（等級 6）。整體印象：昂貴、有意圖、有生命。

## 2. 色盤與角色
- **Canvas White** (#F9FAFB) — 主要背景表面。暖中性，絕不是那種冷冰冰的藍白
- **Pure Surface** (#FFFFFF) — 卡片與容器填色。搭配微弱陰影營造高度差
- **Charcoal Ink** (#18181B) — 主要文字。Zinc-950 的深度——絕不用純黑
- **Steel Secondary** (#71717A) — 內文、說明、metadata。Zinc-500 的暖度
- **Muted Slate** (#94A3B8) — 第三層文字、時間戳、停用狀態
- **Whisper Border** (rgba(226,232,240,0.5)) — 卡片邊框、1px 結構線。半透明以製造層次
- **Diffused Shadow** (rgba(0,0,0,0.05)) — 卡片高度差。大範圍擴散、40px 模糊、-15px 偏移。絕不生硬

### 強調色選擇（每個專案只挑「一個」）
- **Emerald Signal** (#10B981) — 適合成長、成功、正向數據儀表板
- **Electric Blue** (#3B82F6) — 適合生產力、SaaS、開發者工具
- **Deep Rose** (#E11D48) — 適合創意、編輯風、時尚類專案
- **Amber Warmth** (#F59E0B) — 適合社群、社交、暖色調產品

### 禁用色彩
- 紫／紫羅蘭霓虹漸層——也就是「AI 紫」美學
- 純黑（#000000）——永遠改用 Off-Black 或 Zinc-950
- 飽和度超過 80% 的過飽和強調色
- 同一個專案中混用暖灰／冷灰系統

## 3. 字體排印規則
- **Display：** `Geist`、`Satoshi`、`Cabinet Grotesk` 或 `Outfit` — 收緊字距（`-0.025em`）、受控的流體級距、以字重驅動層級（700–900）。不要用吼的。行高壓縮（`1.1`）。強制使用替代字體——`Inter` 在高階情境下一律禁用
- **Body：** 同一字體家族的 400 字重 — 放鬆的行高（`1.65`）、65ch 最大寬度、Steel Secondary 色（#71717A）
- **Mono：** `Geist Mono` 或 `JetBrains Mono` — 用於程式碼區塊、metadata、時間戳。當密度超過等級 7，所有數字都改用等寬字體
- **級距：** Display 用 `clamp(2.25rem, 5vw, 3.75rem)`。Body 用 `1rem/1.125rem`。Mono metadata 用 `0.8125rem`

### 禁用字體
- `Inter` — 在高階／創意情境中一律禁用
- 通用襯線字體（`Times New Roman`、`Georgia`、`Garamond`、`Palatino`）— 禁用。編輯風／創意情境若需要襯線，只能用有辨識度的現代襯線，例如 `Fraunces`、`Gambarino`、`Editorial New` 或 `Instrument Serif`。絕對不要用瀏覽器預設的襯線字體堆疊。不論如何，儀表板與軟體 UI 中永遠禁用襯線

## 4. 元件樣式
* **按鈕：** 扁平表面、無外光暈。主要：強調色填滿＋白字。次要：ghost／outline。active 狀態：`-1px translateY` 或 `scale(0.98)` 做出實體按壓感。hover：細微的背景變化，絕不發光
* **卡片／容器：** 大方的圓角（`2.5rem`）。純白填色。微弱邊框（`1px`、半透明）。擴散陰影（`0 20px 40px -15px rgba(0,0,0,0.05)`）。內部 padding `2rem–2.5rem`。只在「高度差能傳達層級」時使用——高密度版面請用 `border-top` 分隔線或負空間取代卡片
* **輸入／表單：** 標籤放在輸入框上方。輔助文字選用。錯誤文字放在下方，使用 Deep Rose。focus ring 用強調色，`2px` 偏移。不要浮動標籤。label-input-error 這疊之間使用標準的 `0.5rem` 間距
* **導覽：** 俐落、sticky。圖示在 hover 時放大（Dock 放大效果選用）。桌機不要漢堡選單。乾淨的水平排列，間距大方
* **載入器：** 骨架微光（skeletal shimmer），完全貼合版面尺寸與圓角。在佔位形狀上掃過移動的光影。絕不用圓形轉圈
* **空狀態：** 編排過的插畫或圖示構圖，搭配引導文字。絕不只寫「No data found」
* **錯誤狀態：** 行內、貼合情境。紅色強調底線或邊框。清楚的復原動作

## 5. Hero 區塊
Hero 是第一印象——它必須有衝擊力、有創意，絕不能平庸。
- **行內圖像字體排印（Inline Image Typography）：** 把小張、貼合情境的照片或視覺元素直接嵌在標題的字詞或字母之間。範例：「We build [雙手打字的照片] digital [螢幕的照片] products」——圖片以字高行內排列、帶圓角，充當字詞之間的視覺標點。這是招牌創意手法
- **元素不重疊：** 文字絕對不能疊在圖片或其他文字之上。每個元素都有自己清楚的空間區域。內容層不要 z-index 堆疊，不要用絕對定位把標題壓在圖片上。永遠保持乾淨的分隔
- **不要填充文字：** 「Scroll to explore」、「Swipe down」、捲動箭頭圖示、跳動的 chevron，以及任何指示性的 UI 裝飾，一律禁用。使用者知道怎麼捲動。讓內容自然把他們吸進來
- **不對稱結構：** 在這個變異度等級下，置中的 Hero 版面一律禁用。請用分割畫面（50/50）、文字靠左／視覺靠右，或帶大片空白區的不對稱留白
- **CTA 克制：** 最多一個主要 CTA 按鈕。不要放次要的「Learn more」連結。標題底下不要贅述的小字

## 6. 版面原則
- **網格優先：** 所有結構性版面都用 CSS Grid。絕不用 flexbox 百分比運算（`calc(33% - 1rem)` 禁用）
- **不重疊：** 元素絕不能彼此重疊。不要用絕對定位把內容層層疊在內容上。每個元素都佔據自己的網格儲存格或流內位置。乾淨、分離的空間區域
- **功能區塊：** 「三張等寬卡片橫排」這種手法一律禁用。請用兩欄 Zig-Zag、不對稱的 Bento 網格（2fr 1fr 1fr），或水平捲動的展示區
- **寬度限制：** 所有內容置於 `max-width: 1400px` 內並置中。水平 padding 大方（行動 `1rem`、平板 `2rem`、桌機 `4rem`）
- **滿版高度：** 使用 `min-height: 100dvh`——絕不用 `height: 100vh`（iOS Safari 網址列跳動）
- **Bento 架構：** 功能網格請用第 1 列：3 欄｜第 2 列：2 欄（70/30 分割）。每一塊磚都包含一個恆常運作的微動畫

## 7. 響應式規則
每個畫面都必須在所有 viewport 上完美運作。**響應式不是選配，是硬性要求。每一個元素都必須在 375px、768px 與 1440px 下測過。**
- **Mobile-First 收合（< 768px）：** 所有多欄版面嚴格收合成單欄。`width: 100%`、`padding: 1rem`、`gap: 1.5rem`。沒有例外
- **不得水平捲動：** 行動裝置上出現水平溢出屬於重大失敗。所有元素都必須容納在 viewport 寬度內。只要有任何元素造成水平捲動，這個設計就是壞的
- **字級縮放：** 標題透過 `clamp()` 優雅縮小。內文維持最小 `1rem`。絕不把內文縮到 `14px` 以下。標題在 375px 螢幕上必須仍然易讀
- **觸控目標：** 所有互動元素的點擊區至少 `44px`。可點擊項目之間留出大方的間距。行動裝置上按鈕必須滿版寬度
- **圖片行為：** Hero 與行內圖片等比縮放。行內字體排印圖片（夾在字詞之間的照片）在行動裝置上改為堆疊到標題下方，不再行內排列
- **導覽：** 桌機水平導覽收合成乾淨的行動選單（滑入式或全螢幕覆蓋）。不要只有小小的漢堡圖示卻沒有標籤
- **卡片與網格：** Bento 網格與不對稱版面回退成滿版寬度、單欄堆疊的卡片。維持內部 padding（`1rem`）
- **間距一致性：** 垂直區塊間距在行動裝置上等比縮小（`clamp(3rem, 8vw, 6rem)`）。絕不擁擠，也絕不過度空曠
- **測試 viewport：** 設計必須在以下尺寸驗證：`375px`（iPhone SE）、`390px`（iPhone 14）、`768px`（iPad）、`1024px`（小筆電）、`1440px`（桌機）

## 8. 動態與互動（程式階段的意圖）
> **注意：** Stitch 產出的是靜態畫面——它不會做動畫。這一節記錄的是**預期的動態行為**，好讓 coding agent（Antigravity、Cursor 等）在把匯出的設計實作成上線產品時，清楚知道動畫該怎麼寫。

- **物理引擎：** 只用彈簧式。`stiffness: 100, damping: 20`。任何地方都不要線性緩動。所有互動元素都要有高階、有重量的手感
- **恆常微循環：** 每個 active 的儀表板元件都有無限循環狀態——狀態點用 Pulse、搜尋列用 Typewriter、功能圖示用 Float、載入狀態用 Shimmer
- **交錯編排：** 清單與網格以串連延遲掛載（`animation-delay: calc(var(--index) * 100ms)`）。瀑布式揭露，絕不瞬間掛載
- **版面轉場：** 透過共享的 element ID 做平滑重排。項目以物理效果交換位置，模擬即時的智慧感
- **硬體規則：** 只對 `transform` 與 `opacity` 做動畫。絕不動 `top`、`left`、`width`、`height`。顆粒／噪點濾鏡只能掛在固定、`pointer-events-none` 的偽元素上
- **效能：** CPU 吃重的恆常動畫隔離在極小的葉節點元件中。絕不觸發父層重新算繪。目標至少 60fps

## 9. 反面手法（禁用）
- 不要 emoji — UI、程式碼、alt 文字裡都不要
- 不要 `Inter` 字體 — 請用 `Geist`、`Outfit`、`Cabinet Grotesk`、`Satoshi`
- 不要通用襯線字體（`Times New Roman`、`Georgia`、`Garamond`）— 需要襯線時，只用有辨識度的現代襯線（`Fraunces`、`Instrument Serif`）
- 不要純黑（`#000000`）— 只用 Off-Black 或 Zinc-950
- 不要霓虹外光暈或預設的 box-shadow 光暈
- 不要飽和度超過 80% 的過飽和強調色
- 大標題不要用過多的漸層文字
- 不要自訂滑鼠游標
- 元素不得重疊 — 文字絕不疊在圖片或其他內容上。永遠保持乾淨的空間分隔
- 功能區不要三欄等寬卡片版面
- 不要置中的 Hero 區塊（在這個變異度等級下）
- 不要填充式 UI 文字：「Scroll to explore」、「Swipe down」、「Discover more below」、捲動箭頭、跳動的 chevron — 全部禁用
- 不要罐頭姓名：「John Doe」、「Sarah Chan」、「Acme」、「Nexus」、「SmartFlow」
- 不要假的整數：`99.99%`、`50%`、`1234567` — 請用有機的資料：`47.2%`、`+1 (312) 847-1928`
- 不要 AI 文案老套字眼：「Elevate」、「Seamless」、「Unleash」、「Next-Gen」、「Revolutionize」
- 不要會失效的 Unsplash 連結 — 請用 `picsum.photos/seed/{id}/800/600` 或 SVG UI Avatars
- 不要沿用 `shadcn/ui` 的預設樣式 — 請客製圓角、顏色、陰影以符合這套系統
- 不要濫用 `z-index` — 只在 Navbar、Modal、Overlay 這些層級情境使用
- 不要 `h-screen` — 永遠用 `min-h-[100dvh]`
- 不要圓形載入轉圈 — 只用骨架微光
